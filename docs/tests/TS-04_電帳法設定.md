# TS-04 電子帳簿保存法設定（設定 > 電子帳簿保存法設定）

対象:

- `modules/Settings/DocumentsCompliance/models/Module.php`

- `modules/Settings/DocumentsCompliance/views/List.php` / `layouts/v7/modules/Settings/DocumentsCompliance/DocumentsComplianceList.tpl`

## 1. 期待される振る舞い（仕様）

| # | 仕様 |
|---|---|
| S-01 | 入力期限の方針（`prompt` / `cycle`）を画面から切り替えられる |
| S-02 | 猶予営業日数・業務処理サイクル月数・警告営業日数を画面から変更できる |
| S-03 | 方針は選択肢に無い値を拒否する |
| S-04 | 数値は「1以上・上限以下の整数」のみ受け付ける（営業日数・警告日数は 60、サイクル月数は 12） |
| S-05 | 1項目でも不正なら**何も保存しない**（部分保存しない） |
| S-06 | 保存後、現在の設定と「計算例」を返す |
| S-07 | 「再計算」で既存ドキュメントの入力期限を設定値に合わせて更新できる |
| S-08 | 計算例は当日を受領日として、現在の設定で計算した期限と状態を返す |
| S-09 | 本 API はシステム管理者のみ利用できる |
| S-10 | 画面のラベルは言語ファイルから取得し、日本語・英語で切り替わる |
| S-11 | 適合判定で「取引レコード」とみなすモジュールを、**書類区分ごとに**設定できる |
| S-12 | 選択できるモジュールは、ドキュメントの関連リストを持つ有効なモジュールに限る |
| S-13 | 設定済みのモジュールが無効化されても、選択状態が保てるよう候補に残す |
| S-14 | 不正な書類区分・モジュールを含む保存は拒否し、**何も保存しない** |
| S-14b | 保存は**指定された書類区分だけを更新**し、指定が無い区分は現在の設定を維持する<br>（送らなかった区分が黙って既定値に戻らない） |
| S-14c | 空の指定（`{}` / 空配列）は更新対象が無いためエラーにする（誤送信を黙って受け入れない） |
| S-15 | 「適合状態を再判定」で、既存ドキュメントの適合状態を現在の判定基準で洗い替えできる |
| S-15b | 判定基準を変更しても既存ドキュメントは自動では再判定されない。<br>**運用手順は TS-05「1.1.1 判定基準を変更したときの再判定」を参照** |

| 入力 | 期待 |
|---|---|

### BV-4: `category_modules`（書類区分ごとの取引モジュール）

| 入力 | 期待 |
|---|---|
| JSON 文字列 `{"invoice":["Invoice"]}` | `invoice` だけ更新。**他の6区分は現在の設定を維持** |
| 配列（`category_modules[invoice][]=Invoice`） | 同上 |
| 未指定 / `''` / `'abc'`（JSON でない） | 例外 `LBL_INVALID_CATEGORY_MODULES` |
| `{}`（空オブジェクト） / `[]`（空配列） | 例外 `LBL_INVALID_CATEGORY_MODULES`（何も変更しない） |
| 全7区分を指定 | すべて指定どおりに更新 |
| `{"unknown":["Invoice"]}` | 例外 `LBL_INVALID_CATEGORY` |
| `{"invoice":["NoSuchModule"]}` | 例外 `LBL_INVALID_MODULE`（モジュール名を含む） |
| `{"invoice":[]}` | 空配列で保存（`invoice` は関連付けを条件にしない） |
| `{"invoice":"Invoice,SalesOrder"}`（カンマ区切り文字列） | 2件として保存 |
| `{"invoice":["Invoice","Invoice"]}` | 重複除去され1件 |
| `{"invoice":[" Invoice ", ""]}` | trim され空要素は除去される |
