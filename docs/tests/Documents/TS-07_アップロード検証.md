# TS-07 アップロードの検証と失敗時の挙動

対象:

- `modules/Documents/models/Record.php`（`validateUploadedFile()` / `save()`）
- `modules/Documents/Documents.php`（`save_module()` のアップロード失敗分岐・`fileversion` 初期値）
- `modules/Documents/actions/QuickUpload.php`
- 言語ファイル `LBL_UPLOAD_ERR_*`

関連する修正コミット:

- `aaed32d53` アップロード失敗時にファイルの無いドキュメントが登録される不具合を修正
- `eea33a16d` 分割アップロードで2GBまでの添付ファイルに対応

## 1. 期待される振る舞い（仕様）

| # | 仕様 |
|---|---|
| S-01 | アップロードに失敗した場合、**レコードを作らずにエラーを返す**（添付なしのドキュメントを作らない） |
| S-02 | エラーの種類ごとに、原因が分かるメッセージを返す |
| S-03 | サイズ超過のメッセージには実効上限（例: `8 MB`）を含める |
| S-04 | ファイル未選択（既存ファイルを維持する更新）はエラーにしない |
| S-05 | 分割アップロード済みのファイルは、1リクエスト上限の検証をスキップする |
| S-06 | PHP の上限を通過しても vtiger の `upload_maxsize` を超える場合は保存しない |
| S-07 | 更新時にアップロードが失敗した場合、既存のファイル情報（ファイル名・種別・サイズ等）を維持する |
| S-08 | 新規登録時に `fileversion` が未設定なら `1` を設定する |
| S-09 | クイックアップロードは一度に最大10件まで |
| S-10 | クイックアップロードは、ファイル単位で成功・失敗を返す（1件失敗しても他は処理する） |
| S-11 | 親レコードが指定された場合、登録したドキュメントを関連付ける |
