# TS-13 レコードの関連リストからの既存ドキュメント紐づけ

対象（コミット `95a71ba04`）:

- `modules/Documents/apis/RelationAPI.php`
- `modules/Documents/apis/ListAPI.php`（`exclude_parent_id` / `active_only` の追加）
- React: `src/components/Documents/DocumentSelectModal.tsx`
- React: `src/components/Documents/DocumentsRelatedList.tsx`（「既存のドキュメントを選択」ボタン）
- 言語キー `LBL_SELECT_DOCUMENTS` / `LBL_LINK_DOCUMENTS` / `LBL_RELATION_*` ほか

## 1. 期待される振る舞い（仕様）

| # | 仕様 |
|---|---|
| S-01 | レコードの関連リストから、既存のドキュメントを選んで紐づけられる |
| S-02 | 紐づけ・解除は `Vtiger_Relation_Model` を通す（イベントハンドラ・更新履歴が標準と同じ扱いになる） |
| S-03 | 候補は「その親レコードにまだ紐づいていない」「有効な（`filestatus=1`）」ドキュメントのみ |
| S-04 | 候補一覧はフォルダ権限に従う（参照できないフォルダのドキュメントは候補に出ない） |
| S-05 | 指定されたドキュメントは**件数で切り捨てず、すべて処理する**。<br>1リクエストで送れる件数は PHP の `max_input_vars` / `post_max_size` に従う |
| S-06 | 既に紐づいている（解除なら紐づいていない）ものはスキップし、`skipped` に数える |
| S-07 | ドキュメント以外のレコードIDを渡されても関連付けしない |
| S-07b | 参照権限の無いフォルダのドキュメントは紐づけ・解除の対象にしない（`denied` に数える） |
| S-08 | 紐づけ・解除のたびに、電帳法対象ドキュメントの適合状態を再判定する |
| S-09 | 適合の再判定に失敗しても、関連付け自体は成功として扱う |
| S-10 | 親レコードの詳細参照権限と Documents の詳細参照権限が必要 |
| S-11 | 候補一覧はキーワード検索・ページングができる |

## 3. 境界値・同値分割

### BV-1: `records` パラメータ

| 入力 | 期待 |
|---|---|
| `records[]=1&records[]=2`（配列） | 2件を処理 |
| `records=1,2,3`（カンマ区切り） | 3件を処理 |
| `record=1`（単数形） | `records` が空のときのフォールバックとして使われる |
| 未指定 / `''` / `,,` | `LBL_RELATION_NO_RECORD_SELECTED` |
| `0` / `-1` / `'abc'`（→0） | 除外される。すべて除外なら上記の例外 |
| 同じIDを重複指定 | 重複除去され1件として処理 |
| 200件 | すべて処理 |
| 201件 / 500件 | **すべて処理**（件数で切り捨てない） |
| `max_input_vars` を超える件数 | PHP 側で切り詰められる。運用上は画面の選択件数で制御する（S-05） |

### BV-2: `parent_id`

| 入力 | 期待 |
|---|---|
| 未指定 / `0` / `-1` / `'abc'`（→0） | `LBL_RELATION_PARENT_REQUIRED` |
| 存在しないID | `LBL_RELATION_PARENT_NOT_FOUND` |
| 削除済み（`deleted=1`）のID | 同上 |
| `parent_module` と `setype` が食い違うID | 同上（`setype` も条件にしている） |

### BV-3: 候補一覧（`DocumentSelectModal`）

| 状況 | 期待 |
|---|---|
| 候補0件 | `LBL_NO_DOCUMENTS_TO_LINK` を表示 |
| 候補10件（`PAGE_LIMIT`） | 1ページ |
| 候補11件 | 2ページ。ページングが出る |
| 選択0件 | 「紐づける」が押せない（`handleLink` が即 return） |
| 選択1件 / 複数件 | 選択数が表示され、まとめて紐づけられる |
| 検索キーワード入力中 | 300ms のデバウンス後に1回だけ取得。ページが1に戻る |
| モーダル再オープン | ページ・検索語・選択がリセットされる |

### BV-4: 適合状態への波及

| 状況 | 期待 |
|---|---|
| 電帳法対象（書類区分あり）を取引モジュールに紐づけ | `compliant` に変わりうる（TS-05 の判定に従う） |
| 電帳法対象を取引モジュール**以外**に紐づけ | 適合状態は変わらない（不適合のまま） |
| 電帳法対象外（書類区分なし） | 再判定を行わない（`compliance_status` は `null` のまま） |
| 唯一の取引レコードとの紐づけを解除 | `non_compliant` に戻る |
