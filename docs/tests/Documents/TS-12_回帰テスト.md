# TS-12 既存機能への影響（回帰テスト）

本ブランチは Documents モジュールの刷新に加え、共通部分にも手を入れている。
「変えていないはずのものが変わっていない」ことを確認する。

## 1. 変更が及ぶ既存機能

| # | 変更点 | 影響 |
|---|---|---|
| R-01 | Web ドキュメント（`type=W`）の作成導線を削除<br>（`Documents_ListView_Model` / `Documents_Module_Model` / `Vtiger_RelationListView_Model` / `ModuleHeader.tpl`） | 新規作成メニューから消える。既存レコードは残る |
| R-02 | `modules/Vtiger/models/RelationListView.php` の変更 | **コア相当ファイル**。全モジュールの関連リストに影響 |
| R-03 | `Settings_SharingAccess_Module_Model::getSharingModuleList()` に `editstatus != HIDDEN` 条件を追加 | 共有設定の一覧に出るモジュールが変わる |
| R-04 | Documents の一覧・詳細を React 版（`ListRedesign` / `DetailRedesign`）に切替 | 既存の一覧操作（検索・エクスポート等）の導線 |
| R-05 | `modules/Documents/views/InRelation.php` の縮小 | 他モジュールの関連リスト表示 |
| R-06 | `Documents_Record_Model::downloadFile()` をストリーミング化 | 既存のダウンロード全般 |
| R-07 | `Documents::save_module()` の追記（抽出・ハッシュ・履歴・バージョン） | 既存のドキュメント保存全般 |
| R-08 | 翻訳ファイル（`ja_jp` / `en_us` の Documents・Settings）の大幅追加・修正 | 既存画面の文言 |
| R-09 | `e2e/utils/test.ts` のサイドバー検証の修正 | E2E の安定性 |

| R-11 | `composer.json` に `smalot/pdfparser` を追加（コミット `bea107977`） | PDF 抽出の動作／**他パッケージのバージョン** |
| R-12 | `ListAPI` に `exclude_parent_id` / `active_only` を追加 | 既存の一覧取得（未指定時は従来動作） |
| R-13 | `ComplianceChecker::TRANSACTION_MODULES` を廃止し `DEFAULT_*` ＋設定に変更 | 適合判定の結果が既存ドキュメントで変わりうる |
| R-14 | 関連リストに「既存のドキュメントを選択」ボタンを追加 | 関連リストのレイアウト・既存操作 |

> **⚠️ 要確認 (R-11)**: `smalot/pdfparser` の追加はコミット済み（`bea107977`）。
> ただし `composer.lock` には pdfparser の追加以外に **14パッケージの更新**が含まれている。
>
> - 追加: `smalot/pdfparser v2.12.5`
> - 削除: `symfony/polyfill-ctype` / `symfony/polyfill-php81`（他パッケージから参照されていない）
> - 更新（メジャー）: `paragonie/constant_time_encoding 2.7.0 → 3.1.3`、`symfony/deprecation-contracts 2.5.4 → 3.7.0`、`ramsey/collection 1.3.0 → 2.1.1`
> - 更新（マイナー）: `ramsey/uuid 4.2.3 → 4.9.2`、`tecnickcom/tcpdf 6.10.0 → 6.11.3`、`smarty/smarty 4.5.5 → 4.5.6`、`monolog/monolog 2.10.0 → 2.11.0`、`league/uri 6.7.2 → 6.8.0`、`ezyang/htmlpurifier 4.18.0 → 4.19.0`、`dg/rss-php v1.5 → v1.7`、`symfony/http-foundation 5.4.48 → 5.4.50`、`symfony/process 5.4.47 → 5.4.51`、`symfony/polyfill-mbstring`、`symfony/polyfill-php80`
>
> pdfparser 単体の依存は `ext-iconv` / `ext-zlib` / `php >= 7.1` / `symfony/polyfill-mbstring ^1.18` のみで、
> 他パッケージの更新は `composer update` による再解決の副産物。**TC-RG-066〜068 で回帰確認が必要**。
>
> **⚠️ 要確認 (R-02)**: `modules/Vtiger/` はプロジェクト規約上「コア由来＝直接改変しない」対象。
> Documents 固有の変更を `modules/Documents/` 側へ寄せられないか検討が必要。
