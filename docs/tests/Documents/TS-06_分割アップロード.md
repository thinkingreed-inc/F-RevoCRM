# TS-06 分割アップロード（最大2GBの添付ファイル）

対象:

- `modules/Documents/models/Module.php`（サイズ計算のクラスメソッド群）
- `modules/Documents/utils/ChunkUploadStore.php`
- `modules/Documents/apis/ChunkUpload.php`
- `modules/Documents/actions/Save.php`
- React: `src/components/Documents/utils/chunkUpload.ts` / `hooks/useFileUpload.ts`
- マイグレーション `20260616125641_setup_documents_compliance_schema`（ファイルサイズの `BIGINT` 化。TS-11 と共通）

## 1. 期待される振る舞い（仕様）

| # | 仕様 |
|---|---|
| S-01 | 1リクエストの実効上限は vtiger の `upload_maxsize` と PHP の `upload_max_filesize` / `post_max_size` の**最小値** |
| S-01b | php.ini のサイズ表記は整数＋単位のみを解釈する（**仕様**）。<br>`2.5M` のような小数表記は整数部だけを見て `2M` として扱う（切り捨て）。<br>実際の上限より小さく見積もる方向のため、アップロードが失敗する側には倒れない |
| S-02 | 分割送信の1回分は実効上限からマージン（256KB）を引き、64KB 単位に切り下げる。<br>**チャンクサイズは必ず1リクエストの実効上限を下回る**（multipart のオーバーヘッド分を残す） |
| S-03 | 1ファイルの上限は `config.customize.php` の `$documents_upload_maxsize`（既定 2GB） |
| S-04 | 分割アップロードの一時ファイルは `storage/chunk_uploads/<upload_id>/` に置く（外部から参照できない） |
| S-05 | `upload_id` は 32文字の16進。形式に合わないIDは受け付けない（パストラバーサル対策） |
| S-06 | チャンクは 0 始まりの連番で、順番どおりでなければエラーにする |
| S-07 | 受信合計が宣言サイズを超えたらエラーにする |
| S-08 | 他ユーザーの `upload_id` は参照・追記・削除できない |
| S-09 | 結合サイズが宣言サイズと一致しない場合、保存に進まない |
| S-10 | 保存完了後（成功・失敗を問わず）一時ファイルを削除する |
| S-11 | 24時間以上放置された一時ファイルは、新規アップロード開始時に自動削除する |
| S-12 | 開始時に保存先の空き容量（宣言サイズの2倍）を確認する |
| S-13 | 分割アップロード済みのファイルは、1リクエストの上限チェックの対象外にする |
| S-14 | 分割で保存したファイルも、通常保存と同じく項目値・関連付け・変更履歴・ファイルバージョンが処理される |
| S-15 | 2GB のファイルサイズを桁あふれなく保持できる（`BIGINT`） |
| S-16 | クライアントはチャンク送信の一時的な失敗を最大3回まで再試行する |
| S-17 | クライアントは失敗・中断時にサーバーの一時ファイルを破棄する（`mode=abort`） |

| TC-CU-073 | CSRF | `csrfMagicName`/`csrfMagicToken` がある | すべてのリクエストにトークンが含まれる | 自動 |
| TC-CU-074 | 空 | 0ファイルで `upload()` | 何もせず即 return（ローディングにしない） | 自動 |
| TC-CU-075 | 状態 | アップロード中 | `isUploading: true`。完了・失敗のいずれでも `false` に戻る | 自動 |
