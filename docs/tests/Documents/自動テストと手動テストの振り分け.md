# 自動テストと手動テストの振り分け

TS-01〜TS-13 のテストケースを、実行方法で3つに分類したもの。

| 分類 | 意味 | 実行方法 |
|---|---|---|
| **自動** | スクリプトで実行し、合否が機械的に判定できる | `php test/unit/documents/spec/run_all.php` ほか |
| **半自動** | 画面操作が必要だが、E2E / Vitest で自動化できる余地がある | Playwright / Vitest（未整備。現状は手動） |
| **手動** | 環境操作・目視確認が必要で、自動化の費用対効果が低い | 本書の手順に従って実施 |

## 1. 自動テスト（実装済み・実行可能）

### 1.1 実行方法

```bash
# 全件（PHP 8.2 以上で実行すること。理由は §3 を参照）
php8.3 test/unit/documents/spec/run_all.php

# 個別
php8.3 test/unit/documents/spec/spec_TS01_business_day.php
php8.3 test/unit/documents/spec/spec_TS03_deadline.php
php8.3 test/unit/documents/spec/spec_TS05_compliance.php
php8.3 test/unit/documents/spec/spec_TS06_upload.php
php8.3 test/unit/documents/spec/spec_TS08_api.php
```

終了コードは失敗数（0 なら全て成功）。DB を書き換えるため**開発環境でのみ**実行すること。
テストデータは接頭辞 `SPECTEST_` で作成し、終了時に削除する。設定値は退避して書き戻す。

## 4. 実行環境の制約（重要）

**自動テストは PHP 8.2 以上でしか実行できない。**

`composer.lock` の更新により `vendor/composer/platform_check.php` が `PHP >= 8.2` を要求するようになり、
PHP 7.4 では `vendor/autoload.php` の読み込み時点で致命的エラーになる。

```
Composer detected issues in your platform:
Your Composer dependencies require a PHP version ">= 8.2.0". You are running 7.4.33.
```

- 原因: `dg/rss-php v1.5 → v1.7`（`php >= 8.2`）ほか、`league/uri`・`ramsey/collection`・
  `symfony/deprecation-contracts` が PHP 8.1 以上を要求する版に更新された
- 影響: テスト実行だけでなく**アプリケーション本体も PHP 7.4 では起動しない**
- 対応: サポートする PHP バージョンを 8.2 以上に定めるか、`composer.lock` を PHP 7.4 対応の
  組み合わせで作り直すかの判断が必要（TS-12 R-11 / TC-RG-066〜068）

本書の実行例が `php8.3` になっているのはこのため。
