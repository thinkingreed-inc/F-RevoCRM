## 1. 期待される振る舞い（仕様）

| # | 仕様 |
|---|---|
| S-01 | 休祝日は日付ごとに一意。同じ日付を2件登録できない |
| S-02 | 日付・名称は必須。日付は `YYYY-MM-DD` 形式かつ**実在する日付**であること |
| S-02b | 名称の長さは検証しない（**仕様**）。他のモジュールも同様に DB のカラム長に委ねている |
| S-02c | 存在しないレコードの削除はエラーにせず成功として返す（**仕様**）。<br>画面から同じレコードを二重に削除しても失敗表示にしないため（冪等な削除） |
| S-03 | 休日種別（`day_type`）は `holiday` / `workday`。不正値は `holiday` に丸める |
| S-04 | 休日区分（`holiday_type`）は `national` / `company` / `other`。不正値は `company` に丸める |
| S-05 | 追加・更新・削除の後は営業日判定のキャッシュを破棄する |
| S-06 | 「国民の祝日を一括登録」は指定年の祝日を計算して登録し、**既存の同日は上書きしない** |
| S-07 | 一括登録は 2020年以降のみ受け付ける。それ未満は明示的にエラーにする |
| S-08 | 内閣府公表データの取り込みは、対象年の `national` レコードを公表内容に一致させる<br>（追加・名称更新・公表データに無いものの削除） |
| S-09 | 取り込みで `company` / `other` のレコードは削除しない |
| S-10 | 同一日に会社休日が登録済みの場合、公表データ取り込みで `national` に更新する |
| S-11 | 年を指定しない取り込みは、既定で「前年以降」に絞る |
| S-12 | 週休の曜日は 0〜6 のみ受け付け、範囲外は保存前にエラーにする（黙って捨てない） |
| S-13 | 本 API はシステム管理者のみ利用できる |
| S-14 | 外部接続できない環境向けに、CSV ファイルのアップロード取り込みを提供する |

## 3. 境界値・同値分割

| 入力 | 期待 |
|---|---|
| `''` | 例外 `LBL_INVALID_DATE` |
| `2035-1-1`（0埋めなし） | 例外（正規表現不一致） |
| `2035/01/01` | 例外（正規表現不一致） |
| `2035-01-01` | 保存成功 |

| 入力 | 期待 |
|---|---|

| 201文字 | **仕様**: アプリ側で長さ検証は行わず、DB のモードに従う（他モジュールと同じ扱い） |
| `<script>alert(1)</script>` | そのまま保存され、表示時にエスケープされる（XSS にならない） |
