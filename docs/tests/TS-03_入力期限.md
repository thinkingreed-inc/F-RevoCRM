# TS-03 スキャナ保存の入力期限の自動計算

対象:

- `modules/Documents/utils/DeadlineCalculator.php` (`Documents_DeadlineCalculator`)
- `cron/modules/Documents/UpdateInputDeadlineStatus.service`
- `Documents_Record_Model::save()` / `recalculateInputDeadline()`
- `Documents_ComplianceAPI_Api::saveCompliance()` からの再計算

## 1. 期待される振る舞い（仕様）

| # | 仕様 |
|---|---|
| S-01 | 入力期限は **保存区分が `scanner`（スキャナ保存）** かつ **受領日がある** 場合のみ計算する |
| S-02 | 方針 `prompt`（速やかに）: 受領日の翌営業日から数えて N 営業日目が期限（既定 N=7） |
| S-03 | 方針 `cycle`（業務処理サイクル後速やかに）: 受領日に M か月（既定 2）を加えた日を起算日とし、その翌営業日から N 営業日目が期限 |
| S-04 | 月の加算は月末を超えないよう丸める（1/31 + 1か月 = 2/28）。`strtotime('+1 month')` の繰り上がりを使わない |
| S-05 | 期限状態は `within`（期限内）/ `warning`（期限間近）/ `overdue`（期限超過）の3値 |
| S-06 | 期限日が基準日より前なら `overdue` |
| S-07 | 基準日から期限日まで（両端含む）の**営業日数**が警告日数（既定3）以下なら `warning`、超えていれば `within` |
| S-07b | 期限日そのものは超過扱いにしない（**仕様**）。基準日と期限日が同じ日（残り0〜1営業日）は `warning`。<br>期限日の当日はまだ入力できるため、超過は「期限日を過ぎてから」とする |
| S-07c | 受領日・期限日が空・`0000-00-00` の場合は `null` を返し、日付として解釈できない値は `InvalidArgumentException` を投げる（TS-01 S-13b と同じ扱い） |
| S-08 | 保存区分が `scanner` でなくなった場合、期限と期限状態を消す |
| S-09 | 再計算しても値が変わらない場合は UPDATE しない |
| S-10 | 期限状態は日付の経過だけで変化するため、cron で日次に洗い替える |
| S-11 | 設定（方針・日数）は `vtiger_documents_settings` に保持し、未設定なら既定値を使う |
| S-12 | 設定値が不正（非数値・0以下）の場合は既定値にフォールバックする |
| S-13 | 設定テーブルが未作成（マイグレーション前）でもエラーにせず既定値で動作する |
| S-14 | 期限の計算に失敗しても、ドキュメントの保存自体は成功させる（ログのみ） |
| S-15 | 削除済み（`deleted=1`）のドキュメントは一括処理の対象外 |

## 3. 境界値・同値分割

前提（特記なき場合）: 週休 = 土日、`vtiger_holidays` の 2035年・2036年にデータなし、
`policy=prompt`, `business_days=7`, `cycle_months=2`, `warning_days=3`。
2035年1月は 1日(月)〜5日(金) が平日、6日(土)・7日(日) が週休。

### BV-1: 期限の計算（`prompt`）

| 受領日 | 期待する入力期限 | 根拠 |
|---|---|---|
| `2035-01-01`(月) | `2035-01-10`(水) | 1/2〜1/5 で4営業日、1/8〜1/10 で3営業日 |
| `2035-01-05`(金) | `2035-01-16`(火) | 週休を2回跨ぐ |
| `2035-01-06`(土) | `2035-01-16`(火) | 起算日が休日でも「翌営業日から」数える |
| `''` / `'0000-00-00'` / `'abc'` | `null` | DT-1 R1/R2 |

### BV-2: 期限の計算（`cycle`, M=2）

| 受領日 | +2か月 | 期待する入力期限 |
|---|---|---|
| `2035-01-01` | `2035-03-01`(木) | `2035-03-12`(月) |
| `2035-12-31` | `2036-02-29`（閏年の月末に丸め） | 2036年カレンダーで +7営業日 |
| `2035-01-31` | `2035-03-31` | 31日が存在するため丸めなし |

### BV-3: 月加算（`addMonths`）

| 入力 | 期待 |
|---|---|
| `2035-01-31` + 1 | `2035-02-28`（月末に丸め） |
| `2035-12-31` + 2 | `2036-02-29`（閏年） |
| `2035-01-15` + 12 | `2036-01-15`（年跨ぎ） |
| `2035-01-15` + 0 | `2035-01-15` |

### BV-4: 期限状態（`warning_days = 3`）

| 基準日 | 期限日 | 営業日数 | 期待 |
|---|---|---|---|
| `2035-01-08`(月) | `2035-01-07`(日) | − | `overdue`（期限 < 基準日） |
| `2035-01-08` | `2035-01-08` | 1 | `warning` |
| `2035-01-08` | `2035-01-10` | 3 | `warning`（境界: ちょうど警告日数） |
| `2035-01-08` | `2035-01-11` | 4 | `within`（境界: 警告日数 +1） |
| `2035-01-06`(土) | `2035-01-06`(土) | 0 | `warning`（**仕様**: 期限日当日は超過にしない。S-07b） |

### BV-5: 設定値（`getPositiveInt`）

| DB の値 | 期待 |
|---|---|
| 行なし | 既定値 |
| `''` / `'abc'` | 既定値 |
| `'0'` / `'-1'` | 既定値（1未満） |
| `'1'` | 1（下限） |
| `'7'` | 7 |
| `'7.9'` | `is_numeric` 成立 → 7 ⚠️ 要確認（設定画面は整数のみ受理するので通常は発生しない） |

### BV-6: 方針（`getPolicy`）

| DB の値 | 期待 |
|---|---|
| 行なし / `''` / `'PROMPT'` / `'unknown'` | `prompt`（`cycle` 以外はすべて `prompt`） |
| `'cycle'` | `cycle` |
